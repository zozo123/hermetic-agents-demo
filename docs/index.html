Hermetic agents / QA arbitration / Bazel e2e

Code and tests from one spec, with no shared scratchpad.

This demo turns the "hermetic agents" idea into a runnable artifact: a code writer and a test writer receive the same problem spec but different input manifests. The code writer cannot see generated tests. The test writer cannot see implementation. QA reads both outputs plus a hidden oracle and assigns blame when they disagree.

The proof

The generated test suite intentionally contains one wrong expectation: it expects Gizmo to remain capitalized, even though the spec requires case-folding. The implementation returns gizmo. QA compares both sides to the oracle and assigns the disagreement to test_writer.
