Hermetic agents / QA arbitration / Bazel / Crabbox

Code and tests from one spec, with no shared scratchpad.

This demo turns the "hermetic agents" idea into a runnable artifact: a code writer and a test writer receive the same problem spec but different input manifests. The code writer cannot see generated tests. The test writer cannot see implementation. QA reads both outputs plus a hidden oracle and assigns blame when they disagree.

The proof

The generated test suite intentionally contains one wrong expectation: it expects Gizmo to remain capitalized, even though the spec requires case-folding. The implementation returns gizmo. QA compares both sides to the oracle and assigns the disagreement to test_writer. 

{
  "verdict": "test_writer_fault",
  "case": "uppercase-name",
  "blame": "test_writer"
}

Crabbox path

The repo includes a .crabbox.yaml job for delegated Islo execution. Crabbox syncs the checkout, Islo owns the remote sandbox lifecycle, and the run is gated on the proof JSON existing after the command succeeds. 

export CRABBOX_ISLO_API_KEY=ak_...
crabbox job run hermetic-agents

crabbox run --provider islo \
  --require-artifact docs/metrics/hermetic-agents-e2e.json \
  --download docs/metrics/hermetic-agents-e2e.json=.crabbox/proofs/hermetic-agents-e2e.json \
  --shell './scripts/run_hermetic_agents_demo.sh'

Run it

./scripts/run_hermetic_agents_demo.sh
python3 scripts/hermetic_agents_demo.py --self-test
bazelisk test //:hermetic_agents_e2e_test
